# D.A.M VPN for LG — этап 1: Xray на ТВ, SOCKS5 → VLESS + gRPC + TLS (Quattro)

Цель этапа — доказать, что на LG 86UR81006LA (webOS 25, root) Xray устанавливает соединение
VLESS → gRPC → TLS с сервером Quattro и что запрос через локальный SOCKS5 выходит в интернет с другого адреса.
Запуск процесса доказательством не считается (у ProxyTune процесс работал, а `curl` падал с `unexpected eof`).

Этап 1 **не делает**: TUN, маршруты, DNS, ConnMan, файрвол, sysctl, автозапуск, установку, `.ipk`, UI,
FinalMask, TLS-фрагментацию, блокировку QUIC, переход на XHTTP. На ТВ попадает только папка `/tmp/tvvpn`,
`tvctl stop` её удаляет, перезагрузка ТВ — тоже.

Все команды — с Mac, из папки проекта: `cd ~/Documents/Codex/lg-tv-vpn/stage1/mac`.
Пароль root от ТВ спрашивается один раз за 10 минут. Другой адрес ТВ: `TV=root@АДРЕС ./tvctl …`.
Каждый вывод с ТВ проходит фильтр секретов и сохраняется в `reports/` уже без секретов.

## 0. Без ТВ: самопроверка

```sh
./tvctl selftest
```

На фиктивных данных проверяет генератор и его отказы, права 600/700, фильтр секретов, конфиг через
`xray run -test` той же версии (сборка macOS), сценарий start → check → stop на Mac и `.gitignore`.
Ожидается `САМОПРОВЕРКА ПРОЙДЕНА`. На Mac вместо busybox работает `/bin/sh` — поведение на ТВ подтвердит только шаг А.

## Шаг А. Факты о ТВ (только чтение)

```sh
./tvctl facts
```

Ничего не создаёт и не меняет: читает `uname`, `/proc`, заголовки ELF, `ip`, `/etc/resolv.conf`,
`connmanctl services` (без имён сетей), списки процессов и файлов. `iptables` не вызывается (может загрузить модуль ядра).

**Остановиться и решить отдельно, если:**
- часы ТВ расходятся с Mac больше чем на пару минут (ломают проверку сертификата);
- `/tmp` смонтирован с `noexec` или свободно меньше 60 МБ;
- порт 10808 занят;
- остались следы прошлых попыток: `tun0`, маршруты `0.0.0.0/1` или `128.0.0.0/1`, чужие процессы xray/sing-box/tun2socks,
  ConnMan с `IPv6.Configuration` = off или ручными `Nameservers.Configuration`, скрипты в `/var/lib/webosbrew/init.d`.
  Уборка — отдельное решение, этап 1 их не трогает;
- на ТВ нет `curl` (тогда нужна другая схема проверки — тоже отдельное решение).

## Шаг Б. Сборка Xray

Версия закреплена: **v26.10.29**, SHA-256 архивов записаны в `fetch_xray.sh`. Обе сборки для ТВ статические —
от библиотек ТВ не зависят. Выбор — по ABI системы ТВ, строка `ELF /bin/busybox` в отчёте фактов:

| В отчёте | Сборка |
|---|---|
| `ELF64 AArch64` | `linux-arm64-v8a` |
| `ELF32 ARM`, в `Features` есть `vfpv3`/`vfpv4` или `CPU architecture: 8` (ядро aarch64 пишет `fp asimd`) | `linux-arm32-v7a` |
| `ELF32 ARM`, ARMv7 и старше без `vfpv3`/`vfpv4` | `linux-arm32-v6` (только `vfp`) или `linux-arm32-v5` |
| что-то другое | стоп |

Наш ТВ (отчёт 30.10.2026): ядро aarch64, система 32-битная (`ELF32 ARM`, `getconf LONG_BIT` = 32), ARMv8 → `linux-arm32-v7a`.
**Замер 30.10.2026 (`tvctl speedtest`, 20 МБ): `linux-arm32-v7a` упирается в процессор — gRPC ≈30 Мбит/с при ≈91% ядра;
`linux-arm64-v8a` на этом ядре работает — gRPC 120–183 Мбит/с при ≈62%, почти как без VPN (167–185). Для этого ТВ
сборка по умолчанию — `linux-arm64-v8a`.**

```sh
./tvctl fetch linux-arm32-v7a     # пример; сборку берём из таблицы
```

## Шаг В. Ссылка Quattro и конфиг

Ссылку не вставлять в чат и не держать в проекте. Скопировать в буфер ссылку `vless://` одного сервера
(или содержимое подписки целиком) и выполнить:

```sh
umask 077; mkdir -p ~/.config/lg-tv-vpn
pbpaste > ~/.config/lg-tv-vpn/quattro.uri && pbcopy < /dev/null
./tvctl config            # если в файле подписка: ./tvctl config --list, затем ./tvctl config --pick N
```

Если есть только ссылка на подписку (`https://…`): скопировать её в буфер и скачать содержимое, не показывая ссылку
на экране и не оставляя её в истории команд:

```sh
curl -fsSL "$(pbpaste)" > ~/.config/lg-tv-vpn/quattro.uri && pbcopy < /dev/null
```

Если генератор пишет «нет ссылок vless://», подписка отдаётся в другом формате (JSON, шифрованная ссылка Happ) —
стоп, разбираем отдельно. Сводка `config` сохраняется в `reports/` (в ней нет значений, только «задан / не задан»).

Генератор берёт из ссылки только подтверждённые параметры (адрес, порт, UUID, `serviceName`, `mode`, `authority`, `sni`,
`alpn`, `fp`, `flow`, `encryption`) и печатает сводку без значений: «задан, 18 симв.», «совпадает с адресом: нет».
Записывает в `~/.config/lg-tv-vpn` с правами 600: `xray-config.json`, `probe.env` (для проверок на ТВ),
`mask.sed` (фильтр секретов для ТВ). Папку секретов внутри Git-репозитория не принимает.

**Отказ (код 3)**, если ссылка требует: не gRPC (например, XHTTP), не TLS (например, REALITY), `allowInsecure=1`,
Vision-flow (с gRPC Xray его не поддерживает), FinalMask, фрагментацию, ECH, закрепление сертификата или любые
неизвестные параметры. **Код 2** — ссылка повреждена или не найдена. Ссылку не правим наугад: уточняем у Quattro.

## Шаг Г. Запуск, проверка, остановка

```sh
./tvctl push linux-arm32-v7a      # та же сборка, что в шаге Б: Xray и конфиг → /tmp/tvvpn (700/600)
./tvctl start                     # xray run -test, затем запуск; сам остановится через 15 мин (TTL=900)
./tvctl check                     # для приёмки — 3 раза с паузой не меньше минуты
./tvctl stop                      # остановка, удаление /tmp/tvvpn, сверка сети, проверка прямого интернета
```

Что делает `check`:
1. процесс Xray жив;
2. SOCKS5 слушает только `127.0.0.1:10808`;
3. справочно, без Xray: `curl` к серверу Quattro — TCP, TLS с проверкой сертификата, выбран ли HTTP/2;
4. внешний IP напрямую;
5. внешний IP через `socks5h://127.0.0.1:10808` — имя `api.ipify.org` разрешает прокси (в выводе `curl` есть
   «remotely resolved»); IP показывается замаскированным (`185.*.*.*`) и никуда не записывается;
6. 1 МБ через прокси (`speed.cloudflare.com`) — проверка, что туннель держит не только крошечный ответ;
7. журнал Xray: маршрут `socks-in >> quattro`, нет строк с ошибками TLS, gRPC, сети и авторизации;
8. интерфейсы, маршруты, правила и DNS ТВ не изменились с момента `start`.

## Приёмка этапа 1

Этап 1 принят, только если выполнено всё:
- `facts`: архитектура определена, часы в порядке, следов прошлых попыток нет или они разобраны и приняты вами;
- `config`: ссылка принята без отказов; в сводке gRPC, TLS, `allowInsecure=false`, лишних параметров нет;
- `start`: Xray 26.10.29, `Configuration OK.`, процесс жив, слушает только `127.0.0.1:10808`;
- `check` три раза подряд: `ПРОВЕРКА ПРОЙДЕНА` (все пункты ✔), IP через прокси отличается от прямого;
- `stop`: Xray остановлен, `/tmp/tvvpn` удалена, порт закрыт, сеть как до запуска, прямой интернет работает;
- отчёты из `reports/` переданы на разбор; секретов в них нет.

Предупреждение Xray `The feature gRPC transport … is deprecated … migrate to XHTTP` — ожидаемое, не ошибка:
gRPC в v26.10.29 работает, но в будущих версиях его могут убрать. Поэтому версия закреплена,
а переход на XHTTP возможен только если Quattro его поддерживает.

## Диагностика: где именно ломается

Ошибка `curl` через прокси сама по себе причину не показывает. Самопроверка на Mac это подтвердила: при недоступном
сервере Xray принимает SOCKS5-соединение, `curl` получает обрыв (`Connection reset by peer`), а настоящая причина
есть только в журнале Xray. Поэтому разбор — по журналу (шаг 7) и по прямой пробе (шаг 3), снизу вверх:

| Слой | Признаки | Что делать |
|---|---|---|
| Конфиг | отказ генератора (коды 2/3); `start` не прошёл `xray run -test` (`Failed to build`, `unknown "fingerprint"`) | стоп; данные ссылки уточнить у Quattro, не подбирать |
| Сеть | шаг 3: `curl` 6 (DNS) / 7 / 28 (таймаут); журнал: `failed to dial`, `i/o timeout`, `connection refused`, `no such host` | стоп; проверить интернет и DNS ТВ, доступность сервера с другого устройства |
| TLS | шаг 3: `curl` 60; журнал: `x509: certificate is valid for …, not …` (SNI), `x509: certificate has expired or is not yet valid` (часы), `x509: certificate signed by unknown authority`, `remote error: tls:` | стоп; проверку сертификата не отключать никогда; сверить часы и SNI |
| Похоже на DPI | шаг 3: `curl` 35/56; журнал: обрыв (`EOF`, `connection reset by peer`) во время TLS-рукопожатия при рабочей сети | стоп; фрагментация TLS — только отдельным решением |
| gRPC | шаг 3: TLS прошёл, но не HTTP/2; журнал: `rpc error: code = Unimplemented`, `unexpected HTTP status code … 404` или `502` | стоп; сверить `serviceName`, `authority`, порт с Quattro |
| Авторизация | TLS и gRPC без ошибок, но журнал: `failed to decode response header`, `connection ends`; у `curl` обрыв или `unexpected eof` | стоп; проверить подписку (срок, лимит устройств) в Happ на другом устройстве; UUID не менять наугад |
| DNS через прокси | нет «remotely resolved» | проверить версию `curl` на ТВ (нужна поддержка `socks5h`) |
| Локально | Xray завершился сразу после запуска; порт занят | разбор по журналу из вывода `start` |

## Причины немедленной остановки

- любое изменение маршрутов, DNS или интерфейсов в шаге 8 `check` или в `stop` — сразу `./tvctl stop`, отчёт на разбор;
- пропал доступ к ТВ по SSH или интернет на ТВ — перезагрузить ТВ (всё лежит в `/tmp`), затем `./tvctl facts`;
- любой пункт из раздела «Диагностика» — дальше не идём, исправления наугад не делаем.

Ручная остановка без Mac (в SSH на ТВ): `kill "$(cat /tmp/tvvpn/xray.pid)"; rm -rf /tmp/tvvpn` — или перезагрузка ТВ.

## Как скрываются секреты

- Ссылка и всё, что из неё сделано, — только в `~/.config/lg-tv-vpn` (папка 700, файлы 600), вне Git;
  генератор отказывается работать, если папка секретов внутри репозитория; `.gitignore` — страховка; selftest проверяет.
- Генератор печатает только «задан / не задан», длину и тип значения.
- На ТВ: `/tmp/tvvpn` создаётся с `umask 077`; конфиг передаётся по SSH через stdin, без вывода на экран; `stop` удаляет папку.
- Скрипты ТВ пропускают весь свой вывод через `mask.sed`: точные значения UUID, адреса, SNI, `serviceName`, `authority`
  заменяются на `<UUID>`, `<SERVER>`, `<SNI>`, `<SERVICE>`, `<AUTHORITY>`; журнал Xray сам маскирует IP (`maskAddress: full`).
- На Mac весь вывод ТВ проходит второй фильтр (`lgvpn.py redact`): те же значения, а также любые UUID, ссылки `vless://`,
  публичные IP, MAC-адреса, идентификаторы Wi-Fi-сетей, почта, длинные токены — до экрана и до файла в `reports/`.
- Внешние IP показываются только первым октетом и в файлы не пишутся.
- Не использовать `xray run -dump` (печатает конфиг целиком) и не выводить `xray-config.json` на экран.
